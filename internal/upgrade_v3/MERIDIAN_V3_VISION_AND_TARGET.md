# Meridian V3 — Vision and Target

## Immediate V3 purpose

Meridian V3 is the stage where the language should stop feeling merely "promising" and begin feeling like a truly advanced, serious platform language.

V3 is responsible for advancing Meridian beyond the V2 usability core into a language that can credibly compete in **core semantics and runtime power** with modern serious languages.

## Long-term target

The broader target is not only V3.

The real target is **V5 parity-tier maturity** across the major dimensions that make languages like Python, C, Rust, Java, JavaScript, C++, and Ruby powerful:

- core language power,
- memory and safety model,
- runtime and async capabilities,
- standard library breadth,
- tooling and developer experience,
- packaging and ecosystem,
- interop and deployment,
- security and supply chain trust,
- ecosystem depth and adoption,
- documentation/governance/community,
- AI-native legibility and collaboration.

## Role of V3 in that journey

V3 should focus mainly on:
- advanced language core,
- advanced runtime behavior,
- async/concurrency architecture,
- borrowing/lifetime evolution,
- macro/metaprogramming foundations,
- registry/package foundations,
- AI-tooling schemas and advanced developer tooling foundations.

## What V3 should not try to do all at once

V3 should not pretend to finish the entire V5 mission in one step.

Instead:
- **V3** = advanced core and runtime parity foundations,
- **V4** = platform/tooling/registry expansion,
- **V5** = ecosystem/adoption/governance maturity and AI-native leadership.

## Design philosophy

Meridian must remain:
- readable by humans,
- writable by humans,
- analyzable by AI,
- safe by default,
- powerful without becoming chaotic,
- disciplined in complexity.

The language should not become a random feature pile just because the target is ambitious.
